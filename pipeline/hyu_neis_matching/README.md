# 한양대–NEIS 독립 매칭 분석

실행: `python pipeline/match_hyu_neis.py`. API 호출이나 인증키가 필요하지 않다.
기존 web/site_data.json과 NEIS reference.sqlite3를 읽기 전용으로 사용한다.
입력 해시를 기록하고 실행 전후 변하지 않았는지 검증한다. 기존 추천·UI·알레르기 필터와 연결하지 않는다.

## 결과 파일

- `REPORT.md`: 집계·실제 명칭 성공 10개·검토 후보 10개·문제점.
- `summary.json`: 식단 행 기준 메인 매칭 수, 고유 메인명 기준 수, 구성 메뉴 기준 수, 사례.
- `meal_matches.json`: 식단 날짜/식당/카테고리/메인명 키와 구성별 결과.
- `name_matches.json`: 조회명별 완전일치·표기동의어·검토필요·미매칭 결과.
- `main_matches.csv`: 식단 행별 메인명 결과를 확인하는 표.
- `reference_evidence.json`: 명칭 매칭된 NEIS 메뉴의 19종별 표시 학교 수·표시 기록 수·전체 기록 수,
  미표기/검토 수, 학교별 표시 변형, 출처 record_id 목록. 집계 합집합을 한양대 확정 성분으로 쓰지 않는다.
- `evidence_records.jsonl`: 위 집계의 모든 원문 기록. record_id로 학교·급식일자·급식구분·DDISH_NM을 추적한다.

## 매칭과 해석

완전일치: NEIS 원본 메뉴명과 Unicode NFKC·앞뒤 공백 정리 후 같은 경우.
표기동의어: 공백·양끝 별표·영문 대소문자 및 돈까스/돈가스 등 기존 참고 DB의 명시 표기 규칙만 적용해 같은 경우.
치즈, 고기 종류, 소스, 조리명, 중량 등 재료·구성 단서는 임의로 제거하지 않는다.
검토필요: 완전/표기 일치가 없고 문자열 유사도 0.65 이상·공유 문자 2개 이상 후보가 있는 경우.
유사도는 재료 동일성의 증거가 아니다. 후보에는 알레르기 코드를 적용하지 않는다.
미매칭: 이러한 후보도 없는 경우. 사전에 제한된 NEIS 메뉴 표본이라 일치 누락이 가능하다.

성분은 (1) name_explicit_ingredients=메뉴명 명시 단서, (2) neis_possible_ingredients=다른 학교에서 표시된
포함 가능 성분, (3) unknown=실제 배합·미표기 등의 확인 불가 정보로 나눈다.
명칭 단서도 한양대 실물 성분 확인을 뜻하지 않는다. 예를 들어 치즈는 우유 명칭 단서로 남기지만
실제 제품 라벨은 확인되지 않았다. 돈가스소스의 이름에서 돼지고기를 추론하지 않고,
굴림만두에서 굴을 추론하지 않는다. 국수에서 밀, 된장에서 대두 등을 추론하지 않는다.

meal_matches의 main_result는 메인 음식만을 뜻한다. 원문·기존 파싱 자료가 지지하는 구성 메뉴만
component_results에 비교 결과를 넣고, 계산용 대체·분해·가정 추가 구성은 보류한다.
복합명은 더 쪼개지 않는다. 원문 지지는 문자열 확인이며 원래 파서의 경계가 완벽함을 보장하지 않는다.
meal_allergen_union은 항상 null이다. 다른 반찬의 코드를 합쳐 한 끼 확정 성분을 만들지 않는다.
같은 메뉴명의 표시 차이는 기록과 학교 수 및 모든 출처를 유지하고, 부재를 다수결로 판단하지 않는다.
