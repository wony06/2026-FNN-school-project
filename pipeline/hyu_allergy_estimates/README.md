# 메뉴별 알레르기 유발 가능성 분석

실행: `python pipeline/classify_hyu_allergens.py`. API 호출·인증키가 필요하지 않다.
기존 HYU–NEIS 매칭 결과만 읽고 이 폴더에 분석 산출물을 생성한다.
기존 데이터·웹·추천·실제 필터는 변경하지 않으며 입력 해시를 실행 전후 검증한다.

- meal_estimates.json: 식단 449개 × 19종 분류, 구성별 근거·출처 ID·확인 불가·제외 항목.
- meal_allergen_estimates.csv: 식단별 19종 분류를 검토하는 평면 표.
- examples20.json, REPORT.md: 실제 20개 식단과 구성별 판정 근거·학교 출처·문제점.
- reference_statistics.json: NEIS 동일 명칭별 19종 표시 학교 수/표시 기록 수/전체 기록 수,
  미표기/검토필요 수, 학교별 변형, 출처 record_id 목록. 숫자 0은 부재의 증거가 아니다.
- source_records.jsonl: 위 record_id의 학교명·학교코드·급식일자·구분·원문 DDISH_NM.
- summary.json: 분류 집계와 입력 해시.

## 성분 분류

각 성분을 메뉴명단서, NEIS포함가능, 양쪽 근거 있음, 확인불가로 구분한다.
메뉴명 단서도 실제 사용 원재료 확인은 아니다(예: 치즈→우유 명칭 단서).
NEIS 정보는 다른 학교의 동일 명칭 기록이며 한양대 음식의 확정 성분이 아니다.
확인불가는 음성/부재/안전 판정이 아니다. 모든 식단의 실제 조리배합·제품은 확인불가로 남긴다.
검토필요·미매칭 이름에는 유사 후보의 알레르기 정보를 적용하지 않고 이름 단서만 분석한다.

## 구성 메뉴 통합

이전 분석에서 원문 확인이 안 된 계산용 대체·분해·가정 항목 1,128회는 완전히 제외한다.
원문으로 지지되는 구성 메뉴 1,891회와, 계산용 구성요소에 없지만 원래 메뉴명으로
확인되는 메인 82회를 분석한다. 이 추가 82개는 제외된 계산용 항목을 다시 사용하는 것이 아니다.
복합명을 추가 분해하지 않는다. 포함 가능 근거는 구성 ID와 원래 메뉴명을 붙여 보존한다.
식단 단위 집계 시 record_id와 학교코드를 중복 제거하며 구성별 분모를 단순 합산하지 않는다.
선택형(or/또는/선택) 또는 슬래시 의미가 미확인인 식단은 구성 분석만 보존하고 통합은 보류한다.
SELF 안내의 슬래시는 음식 선택지가 아니므로 이 검사에서 제외한다.
보류된 식단의 19종은 모두 확인불가이며 구성별 근거는 별도로 열람할 수 있다.

조개류가 한 학교에서만 표시됐더라도 그 근거를 남긴다. 표시 빈도로 부재를 결정하지 않는다.
소스·양념·제품 배합과 생략된 반찬은 누락될 수 있으며, 반대로 다른 학교의 제품 배합으로
과도하게 경고할 수도 있다. 확정 필터로 사용하기 전에 실제 배합·라벨 확인이 필요하다.
