# 알레르기 자동 연결 (신규 식단)

- `import_selected_menus.py`와 `build_site_data.py` 완료 시 `sync_allergy_data.py`를 자동 실행합니다. 전체 `run_pipeline.py`도 웹 데이터 생성 단계를 통해 동일하게 실행합니다.
- 직접 확인·갱신: `python pipeline/sync_allergy_data.py`. 기존 `export_allergy_web.py` 명령도 같은 갱신을 호출합니다.
- 기존 `hyu_allergy_estimates` 449개 및 NEIS SQLite 원본은 보존합니다. 이후 분석·출처는 이 폴더, 웹용 결과는 `web/allergy-data.json`에 저장합니다.
- 날짜·식당·구분·메뉴명 4개 키로 1:1 연결합니다. 신규·변경 원문만 재분석하며 사진·영양값·계산용 분해 재료는 근거로 추가하지 않습니다.
- 기존 표기 동의어, 사용자 검토, 돈까스 조개류 일부 기록 보류, 선택형 통합 보류 규칙을 그대로 적용합니다. 미표기·미매칭·근거 없음은 미확인이며 안전 판정이 아닙니다.
- 신규 메뉴가 1개인 경우도 지원합니다. 변경이 없으면 웹 JSON을 다시 쓰지 않습니다. 원문 변경·정책 변경은 감지합니다.
- 원문·필수 참조 데이터가 없으면 미확인 또는 오류로 처리하며 유사 메뉴를 자동 확정하지 않습니다. NEIS API 키·새 네트워크 요청은 필요하지 않습니다.
- 데이터 갱신 시 해당 코드·새 분석 자료·`web/allergy-data.json`을 함께 저장합니다. 배포 전에도 전체 메뉴 키와 알레르기 키의 일치 여부를 검사하여 미연결 상태의 공개를 차단합니다. 자동화는 메뉴 수집/웹 데이터 생성 시 실행되며 브라우저가 NEIS를 실시간 조회하는 방식은 아닙니다.

## 파일

- `meal_estimates.json`: 원본과 분리한 신규/변경 식단 분석 캐시
- `reference_statistics.json`, `source_records.jsonl`: 추적 가능한 참조 근거
- `last_batch/`: 마지막 분석 배치의 매칭·분류 결과
- `filter_audit.json`: 원본 근거와 자동 적용 보류 항목을 포함한 최신 내보내기 검산
- `registry.json`: 원문 지문·정책 지문·출력 해시 (검토 승인 표시가 아님)
- `summary.json`: 전체 연결 수·식품별 제외 수

신규 레시피 원재료·제품 라벨과 교차접촉 여부는 확인되지 않았습니다. 공식 원재료 확인은 식당에 별도로 요청해야 합니다.
