# HYU Menu Guide 알레르기 추정 필터

## 구현 범위

기존 NEIS/HYU 원본을 보존하고 별도 web/allergy-data.json을 내보낸다.
식단 연결 키는 `[date, shop, category, main]` 전체 조합이다. 행 순서나 메뉴명만으로 연결하지 않는다.
449개 식단이 정확히 1:1 대응하는지 내보내기와 테스트에서 확인한다.

선택 없음 → 기존 원본 행 그대로 → 기존 PersonalScore와 RecommendationView.
선택 있음 → AllergyFilter.partition에서 OR 조건으로 제외 → 남은 행만 기존 PersonalScore
→ 기존 RecommendationView 정렬. 점수 산식과 남은 행의 계산값은 변경하지 않는다.
제외된 행은 추천 목록에 넣지 않고 별도 접기 영역에서 성분·구성 음식·빈도·출처 예시를 확인한다.
날짜 목록은 필터 전 원본에서 생성해, 전부 제외된 날도 사라지지 않는다.

## 원재료 미확인 처리

남은 모든 메뉴도 원재료 확인 필요 상태다. 실제 배합·교차접촉은 확인되지 않았다.
52개 선택형/슬래시 통합 보류 식단은 성분을 임의 합치지 않고 원재료 확인 필요·추정 통합 보류로 표시한다.
향후 새 식단의 추정 데이터가 미연결이면 unknown으로 유지하고 표시한다.
계산용 가정·분해·대체 1,128회는 원래 검증된 추정 자료에서 제외된 그대로다.
미표기나 특정 번호 비표시로 음성/성분 부재 판정을 하지 않는다.
알레르기 자료 로딩 실패 시 선택 기능을 비활성화하고 오류를 알리며 기존 영양 추천은 계속 동작한다.

## 한정된 조개류 보정

알레르기 18번의 **구성 메뉴별 NEIS 근거**에만 아래 조건을 모두 적용한다.

1. 해당 구성 메뉴명이 돈까스/돈가스를 포함하는 계열이며 소스 단독명이 아니다.
2. 표시 기록 수가 0보다 크고 전체 기록 수보다 작다.
3. 해당 구성 메뉴의 메뉴명 명시 단서에 조개류가 없다.

그 근거만 자동 적용에서 제외하고 미확인 suppressed 항목으로 보존한다.
같은 식단 다른 구성 음식의 조개류 명칭 단서·NEIS 근거는 유지한다.
현재는 실제 원재료 확인 자료가 없으며, 확인된 원재료가 추가되면 보정 규칙보다 그 근거를 우선 연결해야 한다.
전 기록에 표시된 항목, 다른 알레르기 번호, 다른 음식의 일부 표시에는 임의 보정을 하지 않는다.

현재 보정 대상은 고구마치즈돈까스 22개, 등심돈까스 15개로 총 37개 식단이다.
고구마치즈돈가스 조개류 원문 1학교/1표시기록/2전체기록과 출처 ID를 유지한다.
원본 NEIS DB와 기존 추정 JSON은 수정하지 않는다.
다른 일부 조개류 표시 근거 245회는 검토 목록으로 남기고 제거하지 않는다.

## 파일

- pipeline/export_allergy_web.py: 별도 웹 자료·보정 감사 자료 생성.
- pipeline/hyu_allergy_filter_audit.json: 보정 항목, 보존한 부분 표시 항목, 제외 수, 보호 파일 해시.
- web/allergy-data.json: 449개 키·자동 적용 근거·미확인 보정 항목·참조 집계·출처 원문.
- web/allergy-filter.js: 순수 분리 함수. 개인/NRF 점수를 계산하지 않는다.
- web/allergy-ui.js: 다중 선택 드롭다운·선택 요약·미확인 상태·제외 사유.
- web/index.html, web/modern.css: UI 및 기존 추천 함수 앞의 연결.
- web/allergy-filter.test.cjs, pipeline/test_allergy_policy.py: 자료와 정책 회귀 검증.

배포할 때 새 web 파일들도 함께 포함해야 한다. 이 작업에서는 GitHub 작업을 하지 않았다.

## 새 메뉴 반영

1. 기존 절차로 메뉴 원본과 web/site_data.json을 갱신한다.
2. `python pipeline/match_hyu_neis.py`
3. `python pipeline/classify_hyu_allergens.py`
4. `python pipeline/export_allergy_web.py`
5. 아래 검증을 실행하고, 데이터 범위가 늘었다면 기준 건수 변경을 실제 새 자료에 맞춰 검토한다.

새 메뉴가 추가돼도 이 과정 전에는 동일명 임의 연결 없이 미연결·원재료 확인 필요로 표시된다.
classifier의 고정 449/1,128 guard만 상위 매칭 결과의 건수를 읽도록 변경하여 다음 수집도 처리한다.
기존 분석 데이터 파일은 이번 웹 연결 작업에서 재생성하지 않았다.

조개류 자동 적용은 보정 전 250개에서 213개로 변경된다.
수치의 의미는 추정 근거로 제외되는 식단 수이며 실제 성분 확인 비율이나 임상적 정확도가 아니다.
19종 중 일부 번호의 제외 수가 0이더라도 그 성분이 없다는 의미가 아니다.

```text
node --test web/recommendation.test.cjs web/allergy-filter.test.cjs
python pipeline/test_allergy_policy.py
```

12개 JavaScript 테스트와 3개 Python 정책 테스트 통과.
미선택 시 7가지 추천 결과 완전 동일, 선택 시 남은 식단의 계산값 동일 확인.
PC 1440px/모바일 390px 드롭다운 내부 스크롤·선택/해제/완료·화면 넘침·실행 오류 확인.

6/26 고구마치즈돈까스는 조개류만 선택 시 남고, 우유 선택 시 제외됨.
9/14 신소재 미나리돼지곰탕 식단의 비엔나굴소스볶음 명칭 단서는 조개류 근거로 유지됨.
돈까스+바지락국 합성 테스트에서도 돈까스 보정이 반찬 근거를 지우지 않음.
자료 로딩 실패 시 알레르기 선택만 중지되고 기존 메뉴가 로딩되는 것 확인.

## 한계

학교별 제품·소스·육수 배합 차이로 NEIS 근거가 과도하게 넓을 수 있다.
원문에서 생략된 소스·가니시와 해석하지 못한 복합명은 누락될 수 있다.
미확인 메뉴를 확정적인 섭취 가능 목록으로 해석하면 안 된다. 반드시 식당에 원재료·교차접촉을 확인해야 한다.
